# 텔레그램 메시지 포맷

앱이 보내는 텔레그램 메시지 문구를 한곳에 모은 문서다. 문구를 바꾸려면 이 문서와 아래 "소스" 위치를 함께 고친다.

- 기준: `feat/telegram-message-format` (Task 7 이후 포맷 정리)
- 문구 소스: `apps/api/src/main/java/com/lotterypicker/notification/MessageFormatter.java`
- 고지문 소스: `RecommendationSetResponse.DISCLAIMER` (웹 추천 화면과 공유)
- 테스트: `apps/api/src/test/java/com/lotterypicker/notification/MessageFormatterTest.java`

## 공통 규칙

| 항목      | 현재 동작                                                                                          |
| --------- | -------------------------------------------------------------------------------------------------- |
| 전송 방식 | Bot API `sendMessage`, 보내기 전용                                                                 |
| 서식      | **HTML** (`parse_mode: HTML`). `<b>`, `<pre>` 등이 적용된다. 고정 문구 밖의 값에 `<` `>` `&`가 들어가면 이스케이프해야 한다 |
| 날짜      | 추천·추첨 종료·수집 메시지는 `2026-11-09(월)`, 추천 생성 실패 메시지는 `2026-11-09`                |
| 번호      | 오름차순, 두 자리 폭(한 자리는 앞을 공백으로), `" · "`로 구분, `<pre>` 고정폭 블록                   |
| 중복 방지 | `notification_log`의 `(kind, target_key)` 유니크. 같은 알림은 한 번만 보낸다                       |
| 실패 처리 | 5초 간격 최대 3회 시도 후 `FAILED`. 추천은 유지하고 웹 카드에 `텔레그램 발송 실패` 표시. 재발송을 포함해 발송은 최대 3번(누적 9회 시도)까지만 한다 |
| 미설정    | `TELEGRAM_BOT_TOKEN` 또는 `TELEGRAM_CHAT_ID`가 비면 보내지 않고 기록도 남기지 않음 (`SKIPPED`)     |

## 구현된 메시지

### 1. 일일 추천 — `DAILY_RECOMMENDATION`

- **언제:** 매일 17:00 추천 생성 직후. 17시에 서버가 꺼져 있었으면 기동 시 보충(판매 중일 때만, 토요일 20:00 마감)
- **중복 키:** 추천 날짜 (`2026-11-09`)
- **소스:** `MessageFormatter.recommendation(RecommendationSet)` ← `RecommendationJob.notifyRecommendation`

템플릿

```text
{날짜}({요일}) · {회차}회 추천

<pre>{번호1} · {번호2} · {번호3} · {번호4} · {번호5} · {번호6}  {전략 라벨}
… (추천 5줄, 대조군 제외)</pre>

실제 당첨 확률과 무관합니다.
```

예시 (텔레그램 화면, 번호 5줄은 고정폭)

```text
2026-11-09(월) · 1249회 추천

 3 · 11 · 19 · 27 · 38 · 44  최근 빈도
 2 ·  9 · 15 · 23 · 31 · 40  장기 미출현
 1 · 12 · 17 · 27 · 34 · 43  전체 빈도
 5 ·  8 · 21 · 26 · 33 · 45  번호 쌍
 4 · 13 · 20 · 29 · 36 · 41  균형

실제 당첨 확률과 무관합니다.
```

- 번호를 앞, 라벨을 뒤에 둔다. 한글은 고정폭 블록에서도 기기마다 폭이 달라 라벨을 앞에 두면 번호 열이 어긋난다.
- 대조군(`CONTROL`) 줄은 성적표 비교 전용이라 넣지 않는다.
- 줄별 추천 근거(웹 카드에 보이는 문구)와 완화 표시는 메시지에 넣지 않는다.

### 2. 추천 생성 실패 — `RECOMMENDATION_FAILED`

- **언제:** 17:00 생성 또는 기동 보충에서 추천 생성이 예외로 끝났을 때
- **중복 키:** 추천 날짜
- **소스:** `MessageFormatter.recommendationFailed(LocalDate)` ← `RecommendationJob.notifyFailure`

```text
{날짜}(요일) 추천 생성에 실패했습니다.
서버 로그를 확인해 주세요.
```

예시

```text
2026-11-09(월) 추천 생성에 실패했습니다.
서버 로그를 확인해 주세요.
```

### 3. 추첨 종료 — `DRAW_FINISHED`

- **언제:** 새 회차 당첨번호를 수집해 추천과 대조군 채점을 마친 직후 (회차당 1회). 5분 확인, 기동 수집 모두 해당
  - 그 회차 추천이 있으면 항상 보낸다
  - 추천이 없으면 추첨일로부터 7일 이내일 때만 보낸다 (초기 적재로 들어온 지난 회차는 보내지 않음)
  - 발송이 실패했거나 채점 후 보내기 전에 멈췄으면 5분 확인마다 다시 처리해 보낸다. 대상은 추첨일로부터 7일 이내인 최신·직전 회차뿐이다 (`SENT`면 건너뜀, 텔레그램 미설정이면 하지 않음). 지난주 회차를 이번 주에 새 소식처럼 보내지 않기 위해서다
  - 당첨금(3~5등 당첨자 수·금액)이 아직 공개되지 않은 회차는 저장하지 않고 다음 확인에서 다시 받는다. 금액 없이 채점되면 가상 당첨금이 0원으로 굳기 때문이다
- **중복 키:** 회차 (`1249`)
- **소스:** `MessageFormatter.drawFinished(DrawSummary)` ← `PostDrawService.process`

템플릿

```text
{회차}회 추첨 결과 · {추첨일}({요일})
당첨번호를 늦게 수집했습니다({수집 시각}).        ← 늦게 수집했을 때만

<pre>{번호1} · … · {번호6} + {보너스}</pre>

추천 {줄 수}줄 · 최고 {등수}
1등 {n} · 2등 {n} · 3등 {n} · 4등 {n} · 5등 {n} · 낙첨 {n}
가상 당첨금 {합계}원 (구매했다고 가정)
가상 수익 {±수익}원 (줄당 1,000원, {비용}원 구매 가정)

실제 당첨 확률과 무관합니다.
```

예시

```text
1249회 추첨 결과 · 2026-11-07(토)

 3 · 11 · 19 · 27 · 38 · 44 + 7

추천 35줄 · 최고 4등
1등 0 · 2등 0 · 3등 0 · 4등 1 · 5등 3 · 낙첨 31
가상 당첨금 65,000원 (구매했다고 가정)
가상 수익 +30,000원 (줄당 1,000원, 35,000원 구매 가정)

실제 당첨 확률과 무관합니다.
```

추천이 없는 7일 이내 회차

```text
1249회 추첨 결과 · 2026-11-07(토)

 3 · 11 · 19 · 27 · 38 · 44 + 7

이 회차 추천이 없습니다.
```

- 대조군(`CONTROL`) 줄은 줄 수, 등수, 금액 어디에도 넣지 않는다. 대조군도 채점은 하지만 성적표 전용이다.
- 가상 당첨금은 그 회차 등수별 1인당 금액의 합이다. 실제 구매가 아니므로 "구매했다고 가정"을 붙인다.
- 늦게 수집: 추첨 다음 날(일요일) 12:00 이후에 수집한 회차. 시각은 `2026-11-08 13:00` 형식.
- 등수별 줄 수는 한글 라벨 폭이 기기마다 달라 고정폭 블록에 넣지 않고 한 줄로 쓴다.

### 4. 수집 지연 — `COLLECTION_FAILED`

- **언제:** 추첨 다음 날(일요일) 12:00까지 새 회차가 수집되지 않았을 때. 이후 정시 확인마다 다시 요청하지만 키가 같아 1회만 간다
- **중복 키:** 기대 추첨일 = 저장된 최신 회차 추첨일 + 7일 (`2026-11-07`)
- **소스:** `MessageFormatter.collectionFailed(LocalDate)` ← `CollectionJob.poll`

```text
{기대 추첨일}({요일}) 추첨 당첨번호를 아직 수집하지 못했습니다.
수집될 때까지 1시간마다 계속 확인합니다.
```

예시

```text
2026-11-07(토) 추첨 당첨번호를 아직 수집하지 못했습니다.
수집될 때까지 1시간마다 계속 확인합니다.
```

- 없는 결과를 낙첨으로 처리하지 않는다. 수집되면 `DRAW_FINISHED`가 늦게 수집했다는 문장과 함께 간다.

### 5. 수집 오류 — `COLLECTION_ERROR`

- **언제:** 수집기 예외(응답 형식 변경, JSON이 아닌 응답, 요청 실패 등). 5분 확인, 기동 수집, 06:02 판매점 수집 모두 해당
- **중복 키:** 기대 추첨일 = 저장된 최신 회차 추첨일 + 7일. 확인 시간대 밖의 오류도 주 단위로 1회만 간다. 저장된 회차가 하나도 없으면 오늘 기준 이번 주 토요일
- **소스:** `MessageFormatter.collectionError(LocalDate)` ← `CollectionJob.collectRounds` / `collectStores`

```text
{기대 추첨일}({요일}) 추첨 회차 수집 중 오류가 났습니다.
잘못된 값은 저장하지 않았습니다. 서버 로그를 확인해 주세요.
```

예시

```text
2026-11-07(토) 추첨 회차 수집 중 오류가 났습니다.
잘못된 값은 저장하지 않았습니다. 서버 로그를 확인해 주세요.
```

- 수집기는 응답을 파싱한 뒤에만 저장하므로 오류가 나도 잘못된 회차나 낙첨 결과가 생기지 않는다.
- 예외 메시지는 HTML 이스케이프 문제가 있고 사용자에게 의미가 적어 본문에 넣지 않는다.

## 명령 응답

`BotMessageFormatter`. 설정된 채팅(`TELEGRAM_CHAT_ID`)에서 보낸 명령에만 답한다. 다른 채팅은 무응답, 보낸 지 10분 넘은 명령도 무응답. `/start`는 `/help`와 같다. `/round@봇이름 1249`처럼 봇 이름이 붙어도 같은 명령이다.

| 명령 | 답 |
| --- | --- |
| `/help` | `사용할 수 있는 명령` + 줄마다 `/명령 설명` (아래 메뉴 순서) |
| `/today` | 1번 일일 추천과 같은 문구. 오늘 추천이 아직 없으면 앞에 `오늘 추천이 아직 없어 11월 9일 추천을 보여 드립니다. 오늘 추천은 17시에 나옵니다.` + 빈 줄. 추천이 하나도 없으면 `아직 추천이 없습니다.` |
| `/result` | 채점 결과가 있는 가장 최근 회차를 3번 추첨 종료와 같은 문구로. 없으면 `아직 채점한 회차가 없습니다.` |
| `/performance` | 아래 예시. 채점한 줄이 없으면 `아직 채점한 추천이 없습니다.` |
| `/round N` | 아래 예시. 인자가 없거나 1 이상 정수가 아니면 `회차 번호를 숫자로 적어 주세요. 예: /round 1249`, 없는 회차는 `N회 당첨 정보가 없습니다.` |
| `/stats` | 아래 예시(지표마다 상위 5개). 추천이 없으면 `아직 추천이 없어 번호 통계가 없습니다.` |
| `/settings` | `고정 번호: 3, 7` / `제외 번호: 없음` / `바꾸기는 웹의 설정 화면에서 할 수 있습니다.` (보기만) |
| 모르는 명령·일반 글 | `모르는 명령입니다. /help 로 명령 목록을 볼 수 있습니다.` |
| 처리 중 예외 | `처리 중 오류가 났습니다. 잠시 후 다시 시도해 주세요.` |

`/` 메뉴(시작할 때 `setMyCommands`로 등록): today 오늘 추천 · result 최근 회차 채점 결과 · performance 전략별 성적표 · round 회차 당첨 정보 (예: /round 1249) · stats 번호 통계 상위 5개 · settings 고정·제외 번호 보기 · help 명령 목록

`/round 1249`

```
1249회 · 2026-11-07(토)

<pre>16 · 18 · 27 · 36 · 38 · 42 + 22</pre>

1등 15명 · 1,933,658,450원
2등 91명 · 53,122,485원
3등 3,265명 · 1,480,597원
4등 167,745명 · 50,000원
5등 2,723,467명 · 5,000원

1등 판매점 지역
서울 2 · 경기 1 · 온라인 1
```

판매점 지역은 건수 내림차순, 같으면 이름순. 판매점이 없으면 마지막 두 줄 대신 `1등 판매점 정보가 없습니다.`

`/stats`

```
번호 통계 · 11월 10일 추천 기준 (1~1199회)

최근 50회 출현
<pre>27  9회  1위
 7  8회  2위
12  6회  공동 3위
40  6회  공동 3위
 1  5회  5위</pre>

미출현 회차
<pre>33  직전 회차 출현  1위
...</pre>

전체 출현
<pre>43  190회  1위
...</pre>

과거에 자주·드물게 나온 정도일 뿐, 실제 당첨 확률과 무관합니다.
```

미출현 값은 0이면 `직전 회차 출현`, 아니면 `N회째`.

`/performance`

```
전략별 성적표 (채점된 줄 기준)
5등 이상 비율 · 평균 맞힌 개수 · 줄 수
<pre>  2.5%  0.82개  120줄  최근 빈도
  0.0%  0.75개  12줄  대조군 (표본 부족)</pre>
이론값 2.2%

실제 당첨 확률과 무관합니다.
```

대조군은 `/performance`에만 나온다.

## 전략 라벨

`MessageFormatter.label(StrategyType)`

| `StrategyType` | 라벨        | 메시지 포함 |
| -------------- | ----------- | ----------- |
| `RECENT_HOT`   | 최근 빈도   | O           |
| `LONG_COLD`    | 장기 미출현 | O           |
| `ALL_TIME`     | 전체 빈도   | O           |
| `PAIR`         | 번호 쌍     | O           |
| `BALANCED`     | 균형        | O           |
| `CONTROL`      | 대조군      | X (필터됨)  |

## 등수 라벨

`MessageFormatter.rankLabel(PrizeRank)`: `FIRST` 1등 · `SECOND` 2등 · `THIRD` 3등 · `FOURTH` 4등 · `FIFTH` 5등 · `NONE` 낙첨
