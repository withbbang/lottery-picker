# 당첨 판매점 지역 통계 · 지도 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1등(전환 시 2등) 당첨 판매점을 시·도 → 시·군·구 순위로 보여 주고, 지역을 고르면 지도에 판매점 핀을 찍는 화면을 `/rounds/stores`에 만든다.

**Architecture:** API에 `store` 도메인을 새로 두고 집계(지역 추출·순위·판매점 묶기)를 전부 한다. 웹은 한 번의 조회 응답을 그리기만 하고, 지도는 Leaflet + OSM 타일을 클라이언트 전용 컴포넌트 하나에 가둔다. 선택 상태(등수·시도·시군구)는 URL 쿼리에 둔다.

**Tech Stack:** Spring Boot 4.1 / JPA / H2(MySQL 모드) · Next.js 16 / React 19 / React Query / Tailwind v4 / Vitest · Leaflet 1.9.

**Spec:** `docs/superpowers/specs/2026-11-10-stats-share-stores-telegram-design.md` 3장

## Global Constraints

- 숫자 계산·집계는 `apps/api`에서만. 웹은 받은 값을 보여 주기만 한다(지도 `fitBounds`처럼 표시 계산은 예외).
- 응답 포맷·URL·에러 코드는 `api-conventions` 스킬. 새 에러 코드 없음(`COMMON_NOT_FOUND`, `COMMON_VALIDATION_FAILED`만).
- 온라인 판매(주소 `동행복권(dhlottery.co.kr)`)는 지역 "온라인"으로 따로 묶고 지도에서 뺀다.
- **동 단위 목록은 만들지 않는다.** 외부 지오코딩·보정 통계·내 위치 기능 없음.
- 같은 판매점 판정은 이름+주소. `status`(정상/폐점)는 원본대로 표시만.
- 집계 기간 문구: `판매점 정보가 있는 {from}회~{to}회 기준`. 안내 한 줄: `판매점이 많은 지역일수록 당첨도 많이 나옵니다.`
- "당첨 확률을 높인다" 류 표현 금지. "명당" 같은 단어도 쓰지 않는다.
- 지도: OpenStreetMap 타일 + Leaflet, API 키 없음, OSM 저작권 표기 필수, SSR 제외(클라이언트 전용), 지도 코드는 `StoreMap` 한 컴포넌트에만.
- 새 의존성은 `node_modules`의 실제 타입을 읽고 쓴다. 패키지 매니저는 pnpm.
- web 규칙: Tailwind만, `any` 금지, 버튼은 `<button>`·이동은 `<Link>`, import 순서 react → next → 외부 → `@/`. api 규칙: DTO는 record, Entity 노출 금지, Service `@Transactional(readOnly = true)`.

## 이 계획이 정한 것 (스펙이 열어 둔 부분 + 실제 데이터에서 나온 것)

로컬 DB(판매점 66,074행, 262~1249회, 좌표 누락 0건)를 조회해 정했다.

- **시·도 "전남광주"**: 원본 사이트가 지금은 광주·전남을 "전남광주"로 준다(3,304건). 예전에 수집한 행에는 "광주"(308)·"전남"(370)이 남아 있다. 순위가 셋으로 갈라지지 않게 **"광주"·"전남"은 "전남광주"로 합친다.** 전남광주 안의 시·군·구 이름(광산구·여수시…)은 서로 겹치지 않는다.
- **시·군·구 추출**: 주소를 공백으로 나눈 두 번째 토큰이 `시`·`군`·`구`로 끝나면 그 토큰. 즉 `경기 수원시 장안구 …` → `수원시`(일반구는 시에 묶는다. 자치단체 단위라 "우리 동네" 감각과 맞고, 부천시처럼 구가 있다 없다 하는 주소도 한 묶음이 된다). 세종은 모두 `세종`. 그 밖에 규칙에 안 맞는 주소(예: `전남 해보면 …`)는 `기타`.
- **건수의 뜻**: 지역 순위는 당첨 **건수**(같은 판매점이 두 번이면 2). 판매점 순위의 `wins`도 건수.
- **판매점 순위**: 선택 범위에서 당첨 2회 이상인 판매점, 건수 내림차순 → 최근 당첨 회차 내림차순 → 이름, 상위 20개. 전국 범위에서도 보인다.
- **지도 핀**: 시·도를 골랐을 때만(전국은 목록만). 범위 안 좌표 있는 판매점 전부, 온라인 제외. 좌표·상태는 그 판매점의 가장 최근 당첨 행 값. 1회는 작은 원, 2회 이상은 숫자 핀.
- **집계 기간**: 고른 등수 행의 최소~최대 회차.
- **잘못된 지역**: 없는 시·도, 그 시·도에 없는 시·군·구, 시·도 없이 시·군·구만 → `404 COMMON_NOT_FOUND`. 등수는 1·2만(그 밖은 `400`).
- **URL**: `GET /api/v1/store-statistics?rank=1&region=서울&district=중랑구` (기존 `/api/v1/number-statistics`와 같은 모양). 웹 `/rounds/stores?rank=2&region=…&district=…`.
- **캐시**: 수집기는 판매점을 추가만 한다. 등수별 집계 원본을 `(행 수, 최대 id)`가 같은 동안 재사용한다.
