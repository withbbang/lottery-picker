# 추천 줄 복사 · 공유 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 오늘 추천 카드에 줄마다 번호 복사 버튼과, 추천 전체를 기기 공유 시트(없으면 클립보드)로 보내는 공유 버튼을 단다.

**Architecture:** 순수 웹 기능, API 변경 없음. 공유 문구 만들기(`lib/share-text.ts`)와 브라우저 공유·복사(`lib/share.ts`)를 순수 함수로 두고, 버튼 컴포넌트(`components/recommendation/ShareButtons.tsx`)가 결과에 따라 "복사됨" 같은 피드백만 보여 준다. 카드는 버튼을 배치만 한다.

**Tech Stack:** Next.js 16 / React 19 / TypeScript / Tailwind v4 / Vitest + Testing Library. 패키지 매니저 pnpm.

**Spec:** `docs/superpowers/specs/2026-11-10-stats-share-stores-telegram-design.md` 2장

## Global Constraints

- 번호 6개 복사 형식: 0 채움 없이 공백 구분 — `3 7 12 27 33 40`(화면 표시와 같게). 번호는 서버가 준 순서 그대로(웹에서 정렬하지 않는다).
- 공유 텍스트: 첫 줄에 날짜와 회차, 이어서 화면에 보이는 줄들(전략 5줄 + 근거 조합 줄)을 화면과 같은 줄 이름과 함께 한 줄씩. **근거 문구는 넣지 않는다. 대조군은 넣지 않는다.**
- `navigator.share`가 있으면 기기 공유 시트, 없으면 클립보드 복사로 대체하고 "복사됨" 피드백.
- 판매점 표시용 별도 화면은 만들지 않는다. API 변경 없음.
- "당첨 확률을 높인다" 류의 표현은 쓰지 않는다.
- web 규칙: Tailwind만(인라인 `style` 금지), 버튼은 `<button>`, `any` 금지, import 순서 react → next → 외부 → `@/`. 서식은 `.prettierrc.json`(`pnpm lint`가 검사).
- 테스트: 사용자 관점 쿼리(`getByRole`/`getByText`), given/when/then 주석, 테스트 하나에 주제 하나.

## 이 계획이 정한 것 (스펙이 열어 둔 부분)

- 공유 텍스트 정확한 모양(줄바꿈 `\n`):
  ```
  1250회 · 11월 10일 추천
  최근 빈도: 3 7 12 27 33 40
  …
  근거 조합 1: 7 12 24 37 39 40
  실제 당첨 확률과 무관합니다.
  ```
  줄 이름은 `STRATEGY_LABELS`, 근거 조합은 화면처럼 `근거 조합 N`(1부터). 마지막 줄은 응답의 `disclaimer` 그대로 — 남에게 보내는 글이라 화면과 같은 고지를 붙인다.
- 날짜는 응답의 `date`(이월된 추천이면 그 추천 날짜). `monthDay`(`lib/format-date.ts`) 재사용.
- 피드백: 버튼 글자가 2초 동안 "복사됨"으로 바뀌고, 실패하면 2초 동안 "복사 실패". 변경은 `aria-live="polite"` 영역으로 읽힌다.
- 공유 시트를 사용자가 닫으면(`AbortError`) 아무 피드백도 없다. 그 밖의 공유 오류는 클립보드 복사로 대체한다.
- 지난 추천 기록 화면에는 넣지 않는다(스펙상 빌더 재량. 두 용도 모두 오늘 추천이 대상).

## Review Focus

1. 클립보드 API가 없는 환경(http 접속·구형 브라우저) → 예외 없이 "복사 실패"를 보인다. (Task 2·3 테스트)
2. 공유 시트를 닫음(`AbortError`) → "복사됨"도 오류도 없다. (Task 2 테스트)
3. `navigator.share`가 `NotAllowedError` 등으로 실패 → 클립보드로 대체해 "복사됨". (Task 2 테스트)
4. 버튼을 연달아 누름 → 피드백 2초가 마지막 클릭 기준으로 다시 시작되고, 언마운트 뒤 타이머가 상태를 바꾸지 않는다. (Task 3 테스트)
5. 이월된 추천(`carriedOver: true`) → 공유 첫 줄이 오늘이 아니라 그 추천의 날짜·회차다. (Task 1 테스트)

### Task 2: 공유·복사 실행

**Files:**
- Create: `apps/web/lib/share.ts`
- Test: `apps/web/lib/share.test.ts`

**Interfaces:**
- Produces:
  - `type ShareResult = "shared" | "copied" | "cancelled" | "failed"`
  - `copyText(text: string): Promise<"copied" | "failed">` — `navigator.clipboard?.writeText` 사용, 없거나 거부되면 `"failed"`
  - `shareOrCopy(text: string): Promise<ShareResult>` — `navigator.share`가 있으면 `{ text }`로 호출해 `"shared"`, `AbortError`면 `"cancelled"`, 그 밖의 오류나 `share`가 없으면 `copyText` 결과

- [ ] **Step 1: 실패하는 테스트 작성** — `share.test.ts` (`vi.stubGlobal("navigator", …)`로 모킹, 테스트마다 복원)
  - `copies text to the clipboard`: `writeText`가 `"3 7"`로 호출되고 `"copied"`
  - `reports failure when the clipboard is unavailable`: `navigator.clipboard` 없음 → `"failed"`, 예외 없음
  - `reports failure when the clipboard write is rejected`: `writeText`가 reject → `"failed"`
  - `uses the share sheet when available`: `share`가 `{ text }`로 호출되고 `"shared"`, `writeText`는 호출되지 않음
  - `treats a dismissed share sheet as cancelled`: `share`가 `new DOMException("", "AbortError")`로 reject → `"cancelled"`, `writeText` 미호출
  - `falls back to the clipboard when sharing fails`: `share`가 `NotAllowedError`로 reject → `writeText` 호출, `"copied"`
  - `copies when the share sheet is not supported`: `share` 없음 → `"copied"`

- [ ] **Step 2: 실패 확인** — `pnpm vitest run lib/share.test.ts` → FAIL

- [ ] **Step 3: 구현** — 위 시그니처대로.
